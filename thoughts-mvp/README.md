# Thoughts 0.3 — локальные мысли и Expo Update

В версии 0.3 мысли, проекты, настройки оформления и черновик сначала сохраняются на телефоне. Интернет нужен для AI и необязательной копии в Notion. Очередь запускается при восстановлении сети и возвращении в приложение; фоновые задачи дополнительно выполняются по расписанию Android/iOS. Принудительно закрытое приложение продолжит работу после запуска.

Для обновления с версии 0.2 один раз установите новый APK из последнего успешного **Build Thoughts Android APK**. Он связан с Expo-проектом `@tminwws-team/thoughts-ai-inbox`, каналом `preview`, runtime `0.3.0`. Затем совместимые изменения интерфейса публикуются автоматически при изменениях мобильного приложения в ветке `thoughts-ai-inbox-mvp`. Скачанное обновление применяется кнопкой в «Настройки → Обновления» или при следующем запуске. Новые нативные модули требуют нового APK.

В «Настройки → Искусственный интеллект» добавьте OpenRouter API key либо адрес собственного Thoughts API. В «Настройки → Notion» укажите токен интеграции и страницу: локальные мысли и проекты будут отправлены туда, а локальная копия останется. Ключи хранятся в системном защищённом хранилище телефона. Прежние данные собственного сервера можно импортировать отдельной кнопкой; имеющиеся страницы Thoughts в Notion импортируются автоматически.

Проверки: `npm ci`, `npm run check:mobile`, `npm run lint`, `npm test`. Устройство необходимо для проверки микрофона, фоновых задач и получения OTA. Архитектура и гарантии очереди описаны в [docs/local-first.md](docs/local-first.md).

# Thoughts — AI Inbox MVP

Один код React Native / Expo для **Android, iOS и браузера**, отдельный локальный Node.js API, **SQLite**, **Jev** для маршрутизации/классификации и **DeepSeek** для названия/резюме. Оба AI-маршрута по умолчанию идут через OpenRouter. Никакие реальные API-ключи в проект не включены.

## Что уже работает

- Быстрый ввод текста **или голосовая диктовка на русском (ru-RU)**; расшифровку можно проверить и исправить до отправки. Ручной выбор проекта или «Авто».
- **Backend хранит только текст:** никакого загрузочного endpoint для аудио, никакой записи файла голоса. ОС/браузер может использовать собственный облачный speech-сервис; на телефоне доступен переключатель офлайн-распознавания при наличии ru-RU модели.
- Проекты с названиями, описаниями и цветами; описание используется как контекст для классификатора.
- Jev выбирает проект и категорию (`idea / task / bug / research / note`), возвращает confidence. При сомнении запись попадает на проверку.
- DeepSeek создаёт короткое название, резюме и до 4 тегов.
- Поиск, фильтры по статусу/проекту, редактирование заметок и проектов, повторная AI-обработка, удаление.
- Если AI недоступен или не настроен — **оригинальная мысль сохраняется**, обработку можно повторить.
- AI-адаптеры для OpenRouter, OpenAI, прямого DeepSeek и произвольного OpenAI-compatible URL; настраиваемая модель в интерфейсе.
- Jev через Decisions API с возможностью переключить на другой совместимый Decisions endpoint.
- SQLite-хранилище за интерфейсом `StorageAdapter`; JSON-экспорт для миграции и резервной копии.

## 1. Подготовка

**Нужно:** Node.js **22.13+** (лучше актуальная LTS), npm, ключ [OpenRouter](https://openrouter.ai/keys). Проверка API работает без npm-зависимостей благодаря встроенному `node:sqlite`. В Node 22 SQLite помечен как experimental, поэтому запуск использует `--experimental-sqlite`.

Из корня проекта:

```bash
npm install
cp apps/api/.env.example apps/api/.env
cp apps/mobile/.env.example apps/mobile/.env
```

В Windows PowerShell вместо `cp` также можно использовать `Copy-Item`.

Открой `apps/api/.env` и вставь **только на сервере**:

```env
OPENROUTER_API_KEY=sk-or-v1-ВАШ_КЛЮЧ
```

Без ключа можно создать проекты и мысли, но автоматическая обработка будет недоступна до настройки ключа.

## 2. Запуск API

Терминал 1, в **корне проекта**:

```bash
npm run api
```

Проверить: [http://localhost:4000/api/health](http://localhost:4000/api/health). База создаётся автоматически: `apps/api/data/thoughts.sqlite`.

## 3. Браузер

Терминал 2, в корне:

```bash
npm run web
```

Expo выдаст локальный адрес, обычно http://localhost:8081. Должен быть установлен `EXPO_PUBLIC_API_URL=http://localhost:4000` в `apps/mobile/.env`.

**Если Expo просит согласовать версии пакетов с SDK**, после `npm install` выполните `npx expo install --fix` из `apps/mobile` и перезапустите веб-сервер.

## 4. Android / iOS

**Для голосовой функции нужен native development build.** `expo-speech-recognition` — модуль с нативным кодом; в стандартном Expo Go он не работает.

На компьютере с Android SDK:

```bash
cd apps/mobile
npx expo run:android
```

На Mac с Xcode для iOS:

```bash
cd apps/mobile
npx expo run:ios
```

Для следующего запуска dev-клиента можно использовать `npm run mobile` из корня проекта. В браузере `npm run web` не требует нативной сборки и использует Web Speech API. Микрофону требуется разрешение пользователя; веб-версия должна открываться по localhost или HTTPS (для удалённого доступа). Для работы с **физического телефона**:

1. Убедись, что телефон и компьютер в одной доверенной Wi-Fi сети.
2. В `apps/api/.env` поставь `HOST=0.0.0.0` (API станет доступен по локальной сети).
3. В `apps/mobile/.env` поставь `EXPO_PUBLIC_API_URL=http://IP_КОМПЬЮТЕРА:4000`, например `http://192.168.1.25:4000`.
4. Перезапусти API и Expo. Разреши входящие соединения на 4000 в локальном firewall при необходимости.

Для **Android Emulator** можно использовать `http://10.0.2.2:4000` (хост-компьютер из эмулятора). Для iOS Simulator на том же Mac обычно работает localhost.

> **Важно:** это локальный однопользовательский MVP, **без аутентификации и разделения пользователей**. Не выставляй API в публичный интернет, даже если включил `HOST=0.0.0.0`. Перед публичным развёртыванием нужны авторизация, TLS/HTTPS, rate limiting, защита данных и резервное копирование.

## 5. Голосовой ввод (русский)

В поле ввода нажми **«🎙 Диктовать»** и разреши доступ к микрофону. Говори по-русски, дождись окончания распознавания или нажми **«■ Завершить»**. Частичные результаты отображаются сразу, окончательный результат их заменяет. **Сохранение доступно только после окончания диктовки.** Текст можно отредактировать, затем записать в SQLite и обработать AI. Если в поле уже есть текст, диктовка добавится отдельной строкой.

**Политика данных:** `recordingOptions.persist=false`. React Native отправляет в `/api/thoughts` исключительно `{ rawText, projectId }`; backend не принимает `audio/*`, multipart или `audioBase64`. Никакой голосовой записи в базе нет. Однако системный речевой движок может отправить звук своему провайдеру (веб Chrome — Google; Safari/iOS — сервис Apple). Для полной приватности на **Android/iOS** активируй **«Только на устройстве»** при наличии установленного ru-RU языкового пакета: этот режим не переключается автоматически на облако при ошибке. **В браузере локальность распознавания не гарантируется** и функция зависит от браузера (обычно Chrome/Safari). Если распознавание недоступно, текстовый ввод продолжает работать.

Чтобы Android/iOS распознавали речь, нужен отдельный dev build, как указано выше. `expo-speech-recognition` SDK 58 подключён через config plugin и запрашивает разрешение на микрофон и распознавание речи.

## 6. Провайдеры и модели

Настройки доступны в UI на вкладке **Настройки AI** (сохраняются в SQLite):

| Роль | Default | API |
|---|---|---|
| Генерация | `deepseek/deepseek-v4.1-flash-1017` | `https://openrouter.ai/api/v1/chat/completions` |
| Решения/маршрутизация | `typesafe/jev-1.14` | `https://openrouter.ai/api/alpha/decisions` |

**Другие генеративные провайдеры:** в API `.env` добавь ключ `OPENAI_API_KEY`, `DEEPSEEK_API_KEY` либо пару `CUSTOM_AI_BASE_URL` + `CUSTOM_AI_API_KEY`. В UI выбери провайдера и укажи **его собственный** ID модели. Например, если выбран прямой DeepSeek API, OpenRouter ID не подойдёт. Список совместимости поддерживаемых параметров зависит от выбранного провайдера; базовая реализация ожидает Chat Completions с `response_format: {type:'json_object'}`.

**Другие классификаторы:** можно использовать `CUSTOM_DECISIONS_URL` и `CUSTOM_DECISIONS_API_KEY` — endpoint должен понимать формат `model`, `state`, `questions` и выдавать `answers` как OpenRouter Decisions. Для произвольной модели, не поддерживающей этот протокол, потребуется ещё один decision-адаптер.

**Jev и DeepSeek выполняются параллельно** при обработке одной записи. Если один из вызовов падает, второй результат всё равно сохраняется вместе с исходным текстом.

## 7. Хранилища

Сейчас работает `STORAGE_DRIVER=sqlite`. Контракт для новых драйверов: `apps/api/src/storage/contracts.d.ts`, точка подключения: `apps/api/src/storage/index.mjs`.

Чтобы подключить PostgreSQL, Notion или Google Drive, реализуй методы из `StorageAdapter` и добавь драйвер в фабрику. У API и мобильного клиента нет прямого доступа к SQLite, поэтому при переключении хранилища UI и AI-логика сохраняются. Для Notion/Drive понадобится обработка лимитов, пагинации и двусторонних конфликтов.

## 9. Архитектура

```text
apps/
  mobile/
    App.tsx            # интерфейс Android / iOS / Web
    src/useVoiceInput.ts # системная диктовка ru-RU без аудио на сервере
    src/api.ts         # единый HTTP-клиент и типы
  api/
    src/
      server.mjs        # точка входа
      app.mjs           # HTTP API, CRUD, валидация

        index.mjs       # фабрика адаптеров хранилищ
        sqlite.mjs      # текущий SQLite-адаптер
    test/api.test.mjs
```

### Почему не Pi / OpenCode как обязательная зависимость?

Здесь нет сложного агентного цикла или использования инструментов: Jev выбирает категорию, DeepSeek возвращает JSON. Прямые типизированные адаптеры проще, быстрее и безопаснее, чем встраивание coding harness. Впоследствии Pi или OpenCode можно подключить как **отдельного воркера** для многошаговых задач (поиск связей, преобразование идеи в задачи, интеграция с GitHub/Trello). Они не нужны, чтобы сохранить одну мысль.

## HTTP endpoints

`GET /api/health`, `GET /api/config`, `GET|PATCH /api/settings`, `GET|POST /api/projects`, `PATCH|DELETE /api/projects/:id`, `GET|POST /api/thoughts`, `GET|PATCH|DELETE /api/thoughts/:id`, `POST /api/thoughts/:id/process`, `GET /api/export`.

Список мыслей (`GET /api/thoughts`) поддерживает параметры `q`, `projectId` (`inbox` для неназначенных), `status`, `category`, а в рамках MVP возвращает до 500 последних заметок. `/api/export` выгружает **все** записи.

## Что не входит в MVP

Регистрация/аккаунты, облачная синхронизация, мультипользовательский режим, аудиовложения, автономный offline-буфер, OAuth к Notion/Drive, полнотекстовый FTS/векторный поиск, реальный импорт бэкапов, публичный деплой, агентная автоматизация. Это направления следующей итерации, а не скрытые возможности текущей реализации.

## Android APK (GitHub Actions)

APK собирается отдельным workflow в **корне репозитория** `.github/workflows/build-thoughts-apk.yml`. Workflow запускается при изменениях `thoughts-mvp/**` в ветке `thoughts-ai-inbox-mvp`. Открой вкладку **Actions → Build Thoughts Android APK**, открой успешный запуск и скачай артефакт **thoughts-android-apk**. Распакуй ZIP, перенеси `.apk` на Android и установи. Включать «неизвестные источники» следует только для файла из доверенного репозитория.

Это **release-APK, подписанный стандартным debug keystore**, который предназначен только для личного тестирования, не для Play Store. В отличие от debug-APK, он содержит встроенный JS-бандл и не требует Metro. Для публичной публикации нужны отдельный release keystore и безопасное хранение ключей подписи.

После установки открой **Настройки AI → Сервер Thoughts API**, введи URL своего backend (например, `http://192.168.1.25:4000`) и сохрани. Для локальной сети разрешён HTTP в Android-манифесте; не открывай незащищённый API в публичный интернет. Сохранение адреса выполняется только на устройстве через AsyncStorage. Микрофон требует разрешения.

**Важно:** backend **не входит** в APK и должен быть запущен отдельно, без публичного доступа. Автосборка требует доступного npm, Android SDK и GitHub Actions.

## Автоматические обновления интерфейса (EAS Update / Android preview)

**Цель:** один раз установить OTA-enabled APK и дальше получать изменения React Native интерфейса без переустановки. Файлы в `apps/mobile` автоматически запускают workflow `.github/workflows/publish-thoughts-eas-update.yml` и публикуются в **Android `preview`**. Обновления для несовместимых нативных версий не доставляются.

### Одноразовая активация — требуются владелец Expo и его авторизация

Доступа к твоему Expo-аккаунту и прав на изменение GitHub Actions Secrets у CI-агента нет. Не отправляй `EXPO_TOKEN` в чат и не коммить его в репозиторий.

1. Создай или открой аккаунт на https://expo.dev/. На компьютере из `thoughts-mvp/apps/mobile` выполни:
   ```bash
   npx eas-cli@latest login
   npx eas-cli@latest init
   npx eas-cli@latest update:configure --environment preview
   ```
   Команда Expo создаст или привяжет твой EAS-проект и выдаст UUID проекта. Сверь внесённые изменения с динамическим `app.config.js`: у нас `updates.url` и `extra.eas.projectId` устанавливаются через `EXPO_EAS_PROJECT_ID`. Не отключай EAS Update и не меняй `runtimeVersion` без нативной пересборки.
2. В **GitHub → репозиторий `Tminww/ui-note-storage` → Settings → Secrets and variables → Actions → Variables** создай переменную `EXPO_EAS_PROJECT_ID` и вставь UUID из EAS (`xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`).
3. В настройках Expo создай **личный access token** (https://expo.dev/settings/access-tokens). В **GitHub → Settings → Secrets and variables → Actions → Secrets** создай секрет `EXPO_TOKEN`. Храни токен только там, не в коде приложения. У аккаунта должен быть доступ к EAS-проекту.
4. Убедись, что в EAS настроена среда `preview` (expo.dev → Project → Environment variables). Workflow использует `eas update --channel preview --platform android --environment preview`.
5. После настройки открой **GitHub → Actions → Build Thoughts Android APK → Run workflow** для ветки `thoughts-ai-inbox-mvp`. Дождись успешной проверки подписи и **установи APK из артефакта `thoughts-android-apk-ota-enabled`**. Старые APK, собранные без `EXPO_EAS_PROJECT_ID`, никогда не получат EAS Updates: их обязательно заменить один раз.
6. Для проверки запусти workflow **Publish Thoughts EAS Update → Run workflow**. После зелёного статуса открой Thoughts на телефоне. Обновление скачивается при открытии и возвращении в приложение, а кнопка **«Применить»** появляется, когда новая версия готова. При следующем полном запуске загруженное обновление тоже применится.

**Что обновляется:** JS/TS-код, компоненты, стили и встроенные картинки. **Что требует нового APK:** нативные плагины, разрешения, версии Expo SDK/React Native, `app.config.js`, `app.json`, зависимости с нативным кодом.

**Статус:** пока `EXPO_EAS_PROJECT_ID` или `EXPO_TOKEN` отсутствуют, автоматическая публикация неактивна. GitHub job может отображаться `skipped` — это не успешная публикация. Ранее скачанный APK без EAS Project ID также не сможет обновляться автоматически. Вручную запущенный publish workflow покажет точную ошибку настройки, если credentials отсутствуют.

**Отладка:** см. https://docs.expo.dev/eas-update/debug/ и https://docs.expo.dev/eas-update/getting-started/.
