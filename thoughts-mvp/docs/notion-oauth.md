# Подключение Notion через OAuth

Пользователь нажимает «Подключить Notion», разрешает доступ на стороне Notion и выбирает страницу по названию в Thoughts. Если Notion создаёт страницу из шаблона интеграции, Thoughts использует её сразу. Для отдельного проекта можно выбрать другую доступную страницу из того же списка.

## Настройка для владельца приложения

1. В [Notion Developer Portal](https://app.notion.com/developers/connections) создай OAuth-интеграцию с правами читать, добавлять и обновлять контент. Выбери OAuth-интеграцию, которую смогут авторизовать пользователи нужных рабочих пространств. При желании настрой публичный шаблон страницы Thoughts в параметрах интеграции.
2. Укажи HTTPS-адрес возврата, например `https://auth.example.com/notion/oauth/callback`. На том же адресе размести сервис OAuth. Он запускается из `thoughts-mvp` командой `npm run notion-oauth -w @thoughts/api`. Для сервиса задай `NOTION_OAUTH_CLIENT_ID`, `NOTION_OAUTH_CLIENT_SECRET`, `NOTION_OAUTH_REDIRECT_URI`, а также `PORT` и `HOST` по требованиям хостинга. Секрет хранится в окружении этого сервиса.
3. Направь HTTPS-прокси на отдельный OAuth-процесс. Он обслуживает только `/notion/oauth/*`. Не записывай query string callback и тела запросов в логи прокси. Ограничь частоту публичных запросов на прокси. Основной Thoughts API для этого подключения публиковать не нужно.
4. Укажи публичный адрес сервиса без пути в GitHub Actions variable `NOTION_OAUTH_URL` для APK и OTA. Для локальной сборки задай `EXPO_PUBLIC_NOTION_OAUTH_URL` в `apps/mobile/.env`. Следующая сборка или OTA покажет кнопку «Подключить Notion».
5. Проверь Android или iOS с тестовым рабочим пространством. Разреши доступ к одной странице, запиши мысль офлайн, верни сеть и открой синхронизированную копию из приложения.

Сервис обменивает код и обновляет токены через Notion API. Между браузером и приложением передаётся короткоживущий зашифрованный билет, привязанный к конкретному запуску приложения. Токены пользователя сохраняются в SecureStore после выбора страницы. Ручное подключение доступно для сборок без адреса OAuth и для существующих настроек.

## Контейнер и обновления

Workflow **Build Thoughts OAuth container** проверяет OAuth, собирает образ, проверяет HTTP-запуск от непривилегированного пользователя и завершение по SIGTERM, затем публикует образ в `ghcr.io/tminww/thoughts-notion-oauth`. Он запускается при изменениях сервиса в `develop` и `main`. Каждый образ получает тег `sha-<полный commit SHA>`. Дополнительно обновляются теги `develop` и `latest` для соответствующих веток. Для установки используй закреплённый SHA-тег или digest из успешной сборки.

На сервер скопируй каталог `thoughts-mvp/deploy/notion-oauth` в `/opt/thoughts-notion-oauth`. Нужен Docker Compose 2.30 или новее. В этом каталоге подготовь настройки.

```bash
cp .env.example .env
cp oauth.env.example oauth.env
chmod 600 .env oauth.env
```

В `.env` задай `THOUGHTS_OAUTH_IMAGE`, в `oauth.env` — параметры интеграции Notion. `oauth.env` читается в raw-формате, чтобы символы в секрете передавались без подстановок. Если пакет GHCR приватный, перед скачиванием выполни `docker login ghcr.io` с учётными данными для чтения пакета.

```bash
docker compose config --quiet
docker compose pull oauth
docker compose up -d --wait oauth
curl --fail http://127.0.0.1:4010/health
```

Compose использует отдельное имя проекта `thoughts-notion-oauth`, порт `127.0.0.1:4010`, лимит 128 МБ памяти и 0.5 CPU. У процесса нет доступа к Docker socket. Файловая система контейнера доступна только для чтения. В образ входят три файла OAuth-сервиса и Node.js.

После настройки DNS и сертификата сгенерируй отдельную конфигурацию Nginx из шаблона.

```bash
export THOUGHTS_OAUTH_DOMAIN=thoughts-auth.shafranov.tech
envsubst '${THOUGHTS_OAUTH_DOMAIN}' < nginx.conf.template > /tmp/thoughts-notion-oauth.conf
```

Шаблон ожидает сертификат в `/etc/letsencrypt/live/<домен>/`. Проверь, что он уже выпущен. Установи сгенерированный файл как отдельный сайт Nginx, выполни `nginx -t`, затем reload. OAuth-пути логируются без query string и тел запросов.

Для обновления запиши новый закреплённый образ в `.env` и повтори `pull` и `up -d --wait oauth`. Для отката укажи предыдущий образ и повтори эти команды. После замены проверь `/health`. Не удаляй старый образ до проверки входа в Notion. Контейнер хранит сессии в зашифрованных короткоживущих билетах, поэтому постоянный диск ему не требуется.
